# K — مواصفات التقارير (Report Engine)

## 1. المحرك

- كل تقرير **استعلام معرَّف في الكود** (Report Definition): رمز، واسم، ومعاملات (Pydantic)، واستعلام SQL مُعَدّ مسبقًا، وأعمدة، ومجاميع، وصلاحية.
- المصدر دائمًا القيود (`ledger_entries`) أو العروض المبنية عليها، **ولا توجد إجماليات مخزنة من مصدر خارجي**.
- العرض: JSON للمعاينة في الواجهة، و**PDF** (WeasyPrint من قالب HTML عربي RTL مع ترويسة الجهة وتذييل: وقت الإنشاء، ومن أنشأه، ورقم الصفحة، ومعاملات التقرير، وبصمة SHA-256 للمحتوى)، و**Excel** (openpyxl بأرقام حقيقية وتنسيق `#,##0.000` وورقة «المعاملات»)، و**طباعة** (CSS `@media print`).
- التقارير الثقيلة (أكثر من 10,000 سطر) تُنفَّذ في Celery، ويصل إشعار عند الجاهزية.
- كل تصدير يُسجَّل في سجل التدقيق (من صدّر ماذا وبأي فلاتر).
- معاملات مشتركة: السنة المالية، والجهة، والباب، والبند أو مجموعة بنود، ومن/إلى تاريخ، و«الموقف في تاريخ» (As-of)، والحالة، و«تضمين الاستثناءات التاريخية».

## 3. التقرير المركزي (RPT-02)

```
البند | الاعتماد | المناقلات | الارتباطات | المصروف | الرصيد | نسبة التنفيذ
```

| العمود | المعادلة |
|---|---|
| الاعتماد | ControlBase (المفوَّض، أو الاعتماد حسب D-01) |
| المناقلات | TransfersIn − TransfersOut (بإشارة، مع tooltip للوارد والصادر) |
| الارتباطات | Commitments + Reservations القائمة |
| المصروف | Actual |
| الرصيد | Available |
| نسبة التنفيذ | Actual ÷ (الاعتماد + المناقلات)، وفق D-13 |

سطر إجمالي للباب في الأسفل. في PDF: صفحة أفقية (A4 Landscape) مع ترويسة «سجل مراقبة الاعتماد – الباب الثاني – السنة المالية ____ – الجهة ____» للحفاظ على الشكل الرسمي المألوف للنموذج 23/6، مع أرقام صحيحة.
