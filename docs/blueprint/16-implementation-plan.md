# خطة التنفيذ على مراحل

## 1. ملاحظة على ترتيب المراحل المطلوب

الترتيب الوارد في المتطلبات يضع **محرك الرقابة (8)** و**الموافقات (9)** و**التدقيق (13)** بعد المناقلات والارتباطات والمصروفات (5–7). تنفيذه حرفيًا يعني أحد أمرين:
- بناء المناقلات والمصروفات **بدون** فحص رصيد وموافقات ثم إعادة كتابتها لاحقًا، وهذا يخالف شرط «كل مرحلة قابلة للتشغيل والاختبار» ويخالف روح النظام.
- أو وضع بدائل مؤقتة، وهذا يخالف شرط «لا Mock ولا TODO».

**المقترح (قرار D-15):** نقل **دفتر الحركات ومحرك الرقابة** و**محرك الموافقات** و**بنية التدقيق** إلى البداية، مع الإبقاء على نفس المحتوى ونفس عدد المراحل. شاشات التدقيق وتقاريره تبقى في المرحلة 13.

## 3. طريقة العمل في كل مرحلة

1. فرع لكل مرحلة، ثم Pull Request مع وصف ما أُنجز وكيف يُختبر.
2. لا يُدمج كود دون اختباراته.
3. في نهاية كل مرحلة: عرض تشغيلي لما يعمل، وقائمة أي تعارضات جديدة اكتُشفت (بصيغة D-xx) لقرارك.
4. لا بيانات وهمية في الواجهة: الشاشات تعرض بيانات حقيقية من الـ API، وبيانات التطوير تُولَّد عبر نفس خدمات الترحيل.

## 4. ما أحتاجه منك للبدء

1. **الموافقة على المخطط** أو ملاحظاتك عليه.
2. **القرارات D-01 إلى D-15** (ملخصة في [README](README.md#القرارات-المطلوبة)).
3. تأكيد: هل المستودع الحالي هو مكان المشروع؟ (سيُنظَّم كـ monorepo: `backend/` و`frontend/` و`infra/` و`docs/`).
