# D — النموذج المالي (Financial Model)

> هذه الوثيقة أهم وثائق المخطط، وتحتاج **مراجعة وموافقة المحلل المالي** قبل التنفيذ.

## 1. المبدأ

```
Transactions (Ledger)  →  Calculations  →  Reports
```

- **نقطة الرقابة** هي سطر الميزانية = (السنة المالية × الجهة × البند).
- **مصدر الحقيقة الوحيد** هو جدول `ledger_entries`: قيود غير قابلة للتعديل ولا الحذف.
- كل رصيد يُحسب بجمع القيود. جدول `budget_balances` مجرد **ذاكرة مؤقتة** تُحدَّث في المعاملة نفسها، ويُطابَق يوميًا مع مجموع القيود (راجع §7).
- المستند (تفويض، مناقلة، ارتباط، مصروف) **ليس** قيدًا. المستند يولّد قيودًا عند ترحيله فقط.

## 2. مكوّنات الرصيد (Balance Components)

كل قيد يؤثر على **مكوّن واحد** باتجاه (+1 أو −1)، ومبلغه دائمًا موجب.

| المكوّن | الرمز | المعنى |
|---|---|---|
| الاعتماد | `APPROPRIATION` | الاعتماد الأصلي ± التعزيزات والتخفيضات |
| المفوَّض (الموزَّع) | `ALLOCATION` | ما وُزِّع على البند من التفويضات ± تعديلاته |
| مناقلات واردة | `TRANSFER_IN` | |
| مناقلات صادرة | `TRANSFER_OUT` | |
| الحجز المبدئي القائم | `RESERVATION` | طلبات شراء معتمدة لم تتحول لارتباط |
| الارتباط القائم | `COMMITMENT` | ارتباطات معتمدة لم تُسدَّد |
| المصروف الفعلي | `ACTUAL` | |

## 3. المعادلات

لتكن القيم التالية مجموع (الاتجاه × المبلغ) لكل مكوّن في سطر الميزانية:

```
صافي الاعتماد              NetAppropriation = Σ APPROPRIATION
صافي المفوَّض               NetAllocation    = Σ ALLOCATION
أساس الرقابة               ControlBase      = NetAllocation     (إذا كان أساس الرقابة = تفويض أو مستويين)
                                            = NetAppropriation  (إذا كان أساس الرقابة = اعتماد)

الاعتماد بعد المناقلات     AdjustedBudget   = ControlBase + TransfersIn − TransfersOut
الرصيد الدفتري             BookBalance      = AdjustedBudget − Actual
الرصيد المتاح              Available        = AdjustedBudget − Actual − Commitments − Reservations
الاعتماد غير المفوَّض       Unallocated      = NetAppropriation − NetAllocation   (في نمط المستويين فقط)
نسبة التنفيذ الفعلي         ActualRate       = Actual ÷ AdjustedBudget
نسبة الاستخدام             UtilizationRate  = (Actual + Commitments + Reservations) ÷ AdjustedBudget
```

هذه المعادلة هي نفس معادلة المتطلبات:

```
Available = Original Budget + Additional Allocations + Transfers In
          − Transfers Out − Actual Expenditure − Outstanding Commitments − Other Approved Reservations
```

**مثال المتطلبات:**

| المكوّن | المبلغ |
|---|---:|
| الاعتماد الأصلي | 100,000 |
| + مناقلات واردة | 20,000 |
| − مناقلات صادرة | 5,000 |
| = الاعتماد بعد المناقلات | 115,000 |
| − المصروف الفعلي | 60,000 |
| = **الرصيد الدفتري** | 55,000 |
| − الارتباطات القائمة | 10,000 |
| = **الرصيد المتاح** | **45,000** |

النظام يعرض **كل** هذه الأسطر في صفحة البند، وليس الرقم الأخير فقط. ويعرض أيضًا الرصيد الدفتري للتوافق مع Excel (DQ-13).

## 4. محرك الحركات (Transaction Engine): أنواع الحركات وقواعدها

| # | نوع الحركة | الرمز | المكوّن | الاتجاه | يتطلب فحص رصيد؟ | المستند المصدر | قواعد خاصة |
|---|---|---|---|---|---|---|---|
| 1 | اعتماد أصلي | `ORIGINAL_BUDGET` | APPROPRIATION | +1 | لا | مستند ميزانية | مرة واحدة لكل سطر، وقبل فتح السنة أو عند فتحها |
| 2 | توزيع تفويض | `BUDGET_ALLOCATION` | ALLOCATION | +1 | في نمط المستويين: ≤ الاعتماد غير المفوَّض | تفويض | مجموع التوزيعات ≤ قيمة التفويض (FR-AU-03) |
| 3 | تعزيز | `BUDGET_INCREASE` | APPROPRIATION (أو ALLOCATION حسب الأساس) | +1 | لا | قرار تعزيز | |
| 4 | تخفيض | `BUDGET_DECREASE` | APPROPRIATION (أو ALLOCATION) | −1 | **نعم**: المبلغ ≤ المتاح | قرار تخفيض | |
| 5 | مناقلة واردة | `TRANSFER_IN` | TRANSFER_IN | +1 | لا | مناقلة | تُنشأ مع 6 حصرًا |
| 6 | مناقلة صادرة | `TRANSFER_OUT` | TRANSFER_OUT | +1 | **نعم** على البند المصدر | مناقلة | تُنشأ مع 5 حصرًا، بنفس المبلغ والسنة والتاريخ |
| 7 | حجز مبدئي | `PRE_COMMITMENT` | RESERVATION | +1 | **نعم** | طلب شراء | |
| 7ب | تحرير حجز | `RESERVATION_RELEASE` | RESERVATION | −1 | لا | تحويل أو إلغاء طلب الشراء | ≤ الحجز القائم للمستند |
| 8 | ارتباط | `COMMITMENT` | COMMITMENT | +1 | **نعم** (بعد خصم الحجز المحرر في المعاملة نفسها) | أمر شراء، عقد، التزام | |
| 8ب | تسييل ارتباط | `COMMITMENT_LIQUIDATION` | COMMITMENT | −1 | لا | مصروف مرتبط | يولده النظام تلقائيًا، ويساوي min(المصروف، القائم) |
| 9 | مصروف فعلي | `ACTUAL_EXPENDITURE` | ACTUAL | +1 | **نعم** على الجزء غير المغطى بارتباط | مصروف | |
| 10 | تسوية | `ADJUSTMENT` | أي مكوّن | ±1 | **نعم** إذا خفّض المتاح | مذكرة تسوية | سبب وموافقة إلزاميان |
| 11 | قيد عكسي | `REVERSAL` | نفس مكوّن الأصل | عكس الأصل | **نعم** إذا خفّض المتاح (مثل عكس مناقلة واردة استُهلكت) | مذكرة عكس | يعكس **كل** قيود المستند، و`reversal_of_id` إلزامي، ولا يُعكس القيد مرتين |
| 12 | إلغاء | `CANCELLATION` | COMMITMENT أو RESERVATION | −1 | لا | إلغاء ارتباط أو طلب | يحرر الجزء غير المستخدم فقط |
| 13 | إقفال | `CLOSING` | RESERVATION وCOMMITMENT وغيرها | −1 | لا | إقفال السنة | يصفّر القائم في السنة المقفلة |
| 14 | ترحيل للسنة التالية | `CARRY_FORWARD` | COMMITMENT في السنة الجديدة | +1 | يعتمد على D-08 | إقفال السنة | مرتبط بقيد الإقفال المقابل |

### 4.1 ثوابت المحرك (Invariants)، تُختبر آليًا

| رمز | الثابت |
|---|---|
| INV-01 | `amount > 0` و`direction ∈ {+1, −1}` لكل قيد |
| INV-02 | لكل `transfer_group_id`: مجموع TRANSFER_OUT = مجموع TRANSFER_IN، والسنة واحدة، والسطران مختلفان |
| INV-03 | لكل سنة: Σ TRANSFER_IN = Σ TRANSFER_OUT (المناقلات لا تنشئ مالًا) |
| INV-04 | RESERVATION القائم ≥ 0، وCOMMITMENT القائم ≥ 0، لكل مستند ولكل سطر |
| INV-05 | Available ≥ 0 بعد كل ترحيل، إلا إذا كان القيد مغطى بمنحة استثناء (`override_grant_id`) أو مستوردًا كاستثناء تاريخي |
| INV-06 | لا قيد على فترة أو سنة مقفلة |
| INV-07 | القيد لا يُعدَّل ولا يُحذف (Trigger في قاعدة البيانات يرفض UPDATE وDELETE) |
| INV-08 | `budget_balances` = مجموع `ledger_entries` لكل سطر (مطابقة يومية وعند الطلب) |
| INV-09 | القيد العكسي: نفس المبلغ والمكوّن والسطر، باتجاه معاكس، ولا يُعكس القيد مرتين |

## 5. فحص توفر الاعتماد (Budget Availability Check)

```python
def check_availability(line, requested, *, releases=0, override=None) -> CheckResult:
    """
    requested : المبلغ الذي سيستهلك الرصيد المتاح
    releases  : ما سيُحرَّر في المعاملة نفسها (مثل حجز طلب شراء يتحول لأمر شراء)
    """
    # يسبقه دائمًا: التحقق من السنة (مفتوحة)، والفترة (مفتوحة)، والبند (نشط وقابل للترحيل)،
    # وصلاحية المستخدم ونطاقه (سنة، بند، جهة)
    available = balance(line).available + releases
    if requested <= available:
        return OK(available, requested)
    shortfall = requested - available
    if override and override.covers(line, shortfall):
        return OK_WITH_OVERRIDE(available, requested, shortfall, override)
    return INSUFFICIENT(available, requested, shortfall,
        message="لا يوجد اعتماد متاح كافٍ لهذه العملية.")
```

**متى يُنفَّذ الفحص:**

| المرحلة | نوع الفحص | الأثر |
|---|---|---|
| حفظ المسودة | معلوماتي | تحذير في الواجهة فقط |
| التقديم (Submitted) | معلوماتي | تنبيه للمراجع |
| الرقابة على الميزانية (Budget Control) | **إلزامي** | لا يمكن الاعتماد عند العجز |
| الترحيل (Posting) | **إلزامي ونهائي** بقفل `SELECT … FOR UPDATE` على صف `budget_balances` للسطر | يمنع السباق بين عمليتين متزامنتين |

**لماذا الفحص مرتين؟** بين مرحلة الرقابة والترحيل قد تُرحَّل مستندات أخرى على البند نفسه. الفحص الأخير داخل معاملة الترحيل هو الضمان الحقيقي.

## 7. الأداء مع الحفاظ على الحقيقة

- `budget_balances` (صف لكل سطر ميزانية) يحتوي مجموع كل مكوّن وحقل `version`.
- الترحيل يعمل في معاملة واحدة: قفل صف السطر، ثم الفحص، ثم إدراج القيود، ثم تحديث الأرصدة، ثم سجل التدقيق.
- مهمة ليلية (وأيضًا زر «مطابقة الآن») تتحقق من INV-08، وأي فرق يطلق تنبيهًا حرجًا **ولا يُصلَح آليًا**.
- التقارير التاريخية («الموقف في تاريخ X») تُحسب من القيود مباشرة بشرط `entry_date ≤ X`.

## 8. الاختبارات المالية الإلزامية (البند 41)

نمط الارتباط المعتمد: **الصرف على ارتباط يسيّل الارتباط بمقدار المصروف، فلا يتغير المتاح.**

| # | العملية | الاعتماد بعد المناقلات | الفعلي | الارتباط القائم | **المتاح** | ملاحظة |
|---|---|---:|---:|---:|---:|---|
| 1 | اعتماد 100,000 | 100,000 | 0 | 0 | **100,000** | |
| 2 | صرف مباشر 20,000 | 100,000 | 20,000 | 0 | **80,000** | ✔ مطلوب: 80,000 |
| 3 | مناقلة صادرة 10,000 | 90,000 | 20,000 | 0 | **70,000** | ✔ مطلوب: 70,000 |
| 4 | مناقلة واردة 30,000 | 120,000 | 20,000 | 0 | **100,000** | ✔ مطلوب: 100,000 |
| 5 | ارتباط 20,000 | 120,000 | 20,000 | 20,000 | **80,000** | ✔ مطلوب: 80,000 |
| 6 | صرف 15,000 على الارتباط | 120,000 | 35,000 | **5,000** | **80,000** | ✔ الارتباط المتبقي 5,000، والمتاح ثابت |
| 6ب | اختبار إضافي: صرف 6,000 مباشر | 120,000 | 41,000 | 5,000 | 74,000 | |
| 6ج | اختبار إضافي: إلغاء باقي الارتباط | 120,000 | 41,000 | 0 | 79,000 | |
| 6د | اختبار إضافي: صرف مباشر 80,000 | — | — | — | **مرفوض** | العجز = 1,000 |

الرصيد الدفتري بعد الخطوة 6 = 120,000 − 35,000 = **85,000**، والمتاح = **80,000**. الفرق هو الارتباط القائم (5,000).

## 9. الإقفال السنوي (مقترح، يعتمد على D-08)

1. منع مستندات جديدة (حالة السنة: قيد الإقفال).
2. رفض أو إلغاء المستندات غير المرحّلة (بقائمة مراجعة).
3. `CLOSING`: تحرير كل RESERVATION قائم.
4. لكل ارتباط قائم: `CLOSING` (COMMITMENT −1) في السنة القديمة، و`CARRY_FORWARD` (COMMITMENT +1) في السنة الجديدة على البند المحدد في D-08.
5. تقرير الحساب الختامي، ثم حالة السنة: مقفلة.
