# H — المستخدمون والصلاحيات (Permissions Matrix)

## 1. مستويات الصلاحية

| المستوى | الآلية |
|---|---|
| **Module** | الصلاحية بصيغة `module.action` (مثل `transfers.approve`) |
| **Action** | view، create، edit، submit، review، control، approve، post، reverse، cancel، export، admin |
| **Record** | المُنشئ يعدل مسودته فقط، والمعتمد لا يعتمد ما أنشأه (WF-02) |
| **Financial Year** | `user_scopes` من نوع FISCAL_YEAR |
| **Budget Item / Chapter / Entity** | `user_scopes` من نوع ITEM أو CHAPTER أو ENTITY |

تُطبَّق الصلاحيات على مستوى الخادم في كل Endpoint عبر Dependency، ويُطبَّق النطاق بإضافة شرط تلقائي على كل استعلام (Row-Level Filtering) في طبقة المستودع (Repository)، وليس في الواجهة.

## 3. قواعد أمان الصلاحيات

1. **مسؤول النظام لا يملك صلاحيات مالية** (لا اعتماد ولا ترحيل)، فصلًا بين التقنية والمال. وإذا احتاج المستخدم نفسه دورًا ماليًا يُعطى دورًا ثانيًا صراحةً، ويظهر ذلك في تقرير «تعارض الأدوار».
2. **المدقق قراءة فقط** على كل شيء، ولا يستطيع أي إجراء.
3. تغيير الصلاحيات نفسه عملية مُدقَّقة (من غيّر ماذا ولمن).
4. الأدوار الافتراضية الثمانية أدوار نظام لا تُحذف، ويمكن إنشاء أدوار مخصصة.
5. قائمة الصلاحيات الكاملة (`permissions`) تُولَّد من الكود (Single Source) وتُحمَّل بترحيل Alembic.
