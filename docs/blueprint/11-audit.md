# M — استراتيجية التدقيق (Audit Strategy)

## 1. ما يُسجَّل

| الحدث | المصدر | البيانات |
|---|---|---|
| إنشاء أو تعديل أو إلغاء أي سجل مالي أو مرجعي | **Trigger في PostgreSQL** على كل جدول (عدا الجداول التقنية) | الجدول، والسجل، والقيم القديمة والجديدة (JSONB)، والحقول المتغيرة |
| إجراءات الموافقة (تقديم، اعتماد، رفض، إرجاع، ترحيل) | workflow + trigger | المرحلة، والتعليق، ولقطة فحص الرصيد |
| الدخول والخروج وفشل الدخول وقفل الحساب | التطبيق | اسم المستخدم، والنتيجة، وIP، والجهاز |
| تغيير الصلاحيات والأدوار والنطاقات | trigger | |
| التصدير والطباعة | التطبيق | التقرير والفلاتر |
| الاستيراد | التطبيق | الدفعة والقرارات |
| النسخ الاحتياطي والاستعادة | التطبيق | |
| أسئلة المساعد الذكي | `ai_interactions` | السؤال، والأدوات المستدعاة، والمصادر |

## 2. كيف يعرف الـ Trigger المستخدم وعنوان IP؟

في بداية كل معاملة يضبط التطبيق متغيرات جلسة محلية للمعاملة:

```sql
SELECT set_config('gbcfms.user_id',    :user_id,    true),
       set_config('gbcfms.ip',         :ip,         true),
       set_config('gbcfms.user_agent', :ua,         true),
       set_config('gbcfms.request_id', :request_id, true),
       set_config('gbcfms.reason',     :reason,     true);   -- سبب التعديل عند الحاجة
```

ويقرأها الـ trigger بـ `current_setting('gbcfms.user_id', true)`. **أي تعديل بدون مستخدم مضبوط يُرفض** في الجداول المالية، حتى لا يمر تعديل مباشر على قاعدة البيانات دون أثر.

## 3. مقاومة العبث (Tamper Evidence)

- `audit_log` للإضافة فقط (trigger يمنع UPDATE وDELETE، وREVOKE على مستوى الدور).
- **سلسلة Hash:** `row_hash = SHA256(prev_hash || occurred_at || user_id || action || table || record_id || old || new)`، والإدراج متسلسل بقفل استشاري (advisory lock) لضمان ترتيب السلسلة.
- شاشة وAPI «تحقق من سلامة السجل» تعيد حساب السلسلة وتحدد أول سجل مكسور إن وُجد.
- تصدير يومي لآخر Hash (نقطة مرجعية) إلى ملف النسخ الاحتياطي وسجل النظام، فلا يمكن إعادة كتابة السلسلة كاملة دون كشف.

## 4. قواعد عدم الحذف

| الكيان | قبل الترحيل | بعد الترحيل |
|---|---|---|
| المستند المالي | تعديل في Draft وReturned، وإلغاء (Cancelled) مع سبب | لا تعديل ولا حذف، والتصحيح بـ Reversal أو Adjustment |
| القيد | — | لا تعديل ولا حذف أبدًا |
| المرفق | يمكن إزالته من المسودة (يبقى في السجل) | مقفل، ويُسمح بإضافة مرفق جديد فقط |
| المستخدم | Soft delete (`deleted_at`) | — |
| البند | تعطيل (`is_active=false`) | — |

## 5. الاحتفاظ

سجل التدقيق يُحفظ طوال عمر النظام (مقسّم سنويًا عند الحاجة). والأرشفة إلى مخزن بارد تتم بقرار إداري فقط، مع بقاء السلسلة قابلة للتحقق.
