# نظام مراقبة الاعتمادات والمصروفات الحكومية
**Government Budget Control & Financial Monitoring System — GBCFMS**

نظام رقابة على الميزانية (Budgetary Control) يحل محل سجل Excel «الباب الثاني»: التفويضات والتوزيع، والمناقلات، والارتباطات، والمصروفات، والأرصدة، والموافقات، والتدقيق، والتقارير.

**المبدأ:** كل عملية مالية معاملة في دفتر حركات غير قابل للتعديل، والأرصدة والتقارير تُشتق من الحركات. لا يعتمد أي رقم على مجموع مكتوب في Excel.
المعاملات ← الحسابات ← التقارير.

المخطط المهني الكامل وقرارات D-01 إلى D-15: [docs/blueprint/README.md](docs/blueprint/README.md)

## ما يحتويه النظام

| المجال | التنفيذ |
|---|---|
| دفتر الحركات | `ledger_entries` للإضافة فقط (trigger يمنع التعديل والحذف). الأرصدة `budget_balances` تُحدَّث بـ trigger، وتُطابَق دوريًا مع القيود |
| الرقابة على الرصيد | فحص تلقائي عند كل اعتماد: أي نقص في المتاح يُرفض ما لم يوجد استثناء ممنوح (D-10). الأقفال بترتيب ثابت ضد التزامن |
| المستندات | اعتماد أصلي وتعزيز وتخفيض، وتفويضات وتوزيعها، ومناقلات، وطلبات شراء وارتباطات (مع التحويل والتسييل)، ومصروفات، وتسويات وقيود عكسية. لكل مستند ترقيم ومرفقات ودورة موافقة |
| الموافقات | مراجعة مالية ← رقابة الميزانية ← مشرف (حسب شريحة المبلغ) ← اعتماد نهائي، مع فصل المهام والتفويض المؤقت ومهل المراحل |
| التدقيق | كل كتابة في كل جدول تُسجَّل بسلسلة SHA-256 يمكن التحقق منها من الواجهة |
| التقارير | 20 تقريرًا بصيغ PDF (خط عربي مضمَّن) وExcel وطباعة، ولكل تقرير بصمة تحقق |
| الاستيراد | محرك استيراد لسجل Excel يعطي تقرير جودة بيانات، ويتطلب قرارات صريحة للحالات الغامضة، ويستورد عبر محرك الترحيل نفسه (فصل المهام بين المحضّر والمنفّذ) |
| التنبيهات | 14 قاعدة حتمية: الاستنفاد والتجاوز، والتكرار، والمبالغ غير المعتادة، وتجزئة المشتريات، والمبالغ المستديرة، والصرف بلا ارتباط، وارتفاع الصرف في نهاية السنة، والموافقات المتأخرة، وغيرها |
| الإقفال السنوي | تحرير الحجوزات، وترحيل الارتباطات إلى السنة التالية (D-08) في معاملة واحدة، وإقفال الفترات الشهرية |
| الأمان | Argon2id، وJWT قصير العمر مع تدوير Refresh وكشف إعادة الاستخدام، وقفل الحساب، وحد المعدل، وصلاحيات بـ 76 إذنًا و8 أدوار ونطاقات (سنة، جهة، باب، بند) |
| النسخ الاحتياطي | نسخ يومي مشفَّر (AES-256-GCM) مع التحقق، والاستعادة من الواجهة، ونسخة تلقائية قبل الاستعادة |
| المساعد الذكي | اختياري ومعطل افتراضيًا، وللقراءة فقط. كل رقم في إجابته يُتحقق من وجوده في بيانات النظام، ولا يُرسل إليه إلا أرقام مجمعة (D-14). راجع [12-ai.md](docs/blueprint/12-ai.md) |

**التقنيات:** PostgreSQL 16، وFastAPI، وSQLAlchemy 2، وAlembic، وPydantic 2 · React 18، وTypeScript، وTailwind، وTanStack Query، وRecharts، وdecimal.js (المبالغ لا تتحول إلى أرقام عشرية تقريبية في أي طبقة) · واجهة عربية RTL.

## التشغيل على Windows

**ابدأ من `INSTALL.cmd` في جذر المشروع** (نقرتان)، وبعد التثبيت شغّل النظام دائمًا من **`START.cmd`**.
يختار الملفان الطريقة المناسبة تلقائيًا: Docker Desktop إن كان يعمل، وإلا التثبيت المباشر المشروح أدناه.

### التشغيل المباشر (بدون Docker)

مناسب للأجهزة التي لا تدعم المحاكاة الافتراضية، أو التي يتوفر فيها PostgreSQL وPython مسبقًا.

**المتطلبات:** PostgreSQL 13 أو أحدث، وخدمته تعمل، وكلمة مرور المستخدم `postgres` معروفة · Python 3.11 أو أحدث (مع خيار «Add python.exe to PATH») · اتصال إنترنت في التثبيت الأول فقط. لا يلزم Node.js، فالواجهة مبنية مسبقًا في `windows-local/web`.

1. حمّل المشروع (Code ← Download ZIP) وفك الضغط في مجلد مثل `C:\GBCFMS`.
2. افتح مجلد **`windows-local`** وانقر نقرتين على **`install.cmd`**. سيطلب منك:
   - كلمة مرور المستخدم `postgres`، لينشئ مستخدمًا خاصًا بالنظام وقاعدة بيانات `gbcfms`.
   - كلمة مرور جديدة للمسؤول `admin`.
   ثم يعرض مفتاح تشفير النسخ الاحتياطية: **احفظه خارج الجهاز**.
3. انقر نقرتين على **`start.cmd`**. يفتح المتصفح على `http://localhost:8080`. أبقِ النافذة مفتوحة أثناء العمل؛ إغلاقها يوقف النظام.

| الملف (في `windows-local`) | الغرض |
|---|---|
| `start.cmd` | تشغيل النظام (يحدّث قاعدة البيانات تلقائيًا بعد أي تحديث) |
| `backup.cmd` | نسخة احتياطية فورية في `data\backups`. النسخ اليومي يعمل تلقائيًا ما دام النظام يعمل |
| `backup-key.cmd` | عرض مفتاح تشفير النسخ |

**ملاحظات:**
- الإعدادات والأسرار في `backend\.env`: لا تشاركه، واحفظ نسخة منه خارج الجهاز.
- للوصول من أجهزة أخرى في الشبكة: `http://<اسم الجهاز أو عنوان IP>:8080`، مع السماح بالمنفذ 8080 في جدار حماية Windows.
- تصدير PDF يحتاج مكتبات GTK غير الموجودة في Windows افتراضيًا. البديل: زر «طباعة» ثم «حفظ بصيغة PDF» من المتصفح، أو تصدير Excel.

### التشغيل باستخدام Docker Desktop

1. ثبّت **Docker Desktop** من https://www.docker.com/products/docker-desktop/ ، وأعد تشغيل الجهاز إن طُلب منك ذلك، ثم افتحه وانتظر حتى يعمل.
2. حمّل المشروع: من صفحة المستودع على GitHub اختر الفرع `claude/brave-noether-pd8rpv` ثم **Code ← Download ZIP**، وفك الضغط في مجلد مثل `C:\GBCFMS`. أو استخدم `git clone` إن كان Git مثبتًا.
3. افتح مجلد `windows` وانقر نقرتين على **`install.cmd`**. يبني السكربت النظام ويشغّله (وتُولَّد الأسرار تلقائيًا داخل الحاويات)، ثم يطلب كلمة مرور المسؤول `admin` ويفتح المتصفح على `https://localhost`.
4. شغّل **`backup-key.cmd`** واحفظ المفتاح الظاهر خارج الجهاز. بدونه لا يمكن استعادة النسخ الاحتياطية على جهاز آخر.

عند فتح الموقع سيحذّر المتصفح من الشهادة لأنها موقعة ذاتيًا. اختر «متقدم» ثم «المتابعة».

| الملف (في مجلد `windows`) | الغرض |
|---|---|
| `start.cmd` / `stop.cmd` | تشغيل النظام وإيقافه. البيانات تبقى محفوظة |
| `backup-key.cmd` | عرض مفتاح تشفير النسخ الاحتياطية لحفظه |
| `backup.cmd` | نسخة احتياطية فورية في مجلد `backups`. النسخ اليومي يعمل تلقائيًا ما دام النظام يعمل |
| `update.cmd` | نسخة احتياطية ثم تحديث (يتطلب Git) |
| `logs.cmd` | عرض السجلات عند حدوث مشكلة |

**ملاحظات:**
- إن كان المنفذ 443 أو 80 مستخدمًا من برنامج آخر: انسخ `deploy\env.example` إلى `.env` في مجلد المشروع، وغيّر `HTTPS_PORT` و`HTTP_PORT` (مثلًا 8443 و8080)، ثم شغّل `start.cmd`.
- للوصول من أجهزة أخرى في الشبكة استخدم `https://<اسم الجهاز أو عنوان IP>`، واسمح بالمنفذ في جدار حماية Windows.

## التشغيل في بيئة الإنتاج (خادم Linux)

المتطلبات: Linux مع Docker وDocker Compose v2.

```bash
make init        # مجلد backups/. الأسرار تُولَّد تلقائيًا عند أول تشغيل، و.env اختياري
# الشهادة: ضع server.crt وserver.key من CA الجهة في deploy/certs، وإلا تُولَّد شهادة موقعة ذاتيًا تلقائيًا
make build
make up          # يرحّل المخطط تلقائيًا ثم يشغّل nginx وapi وscheduler وpostgres
make bootstrap   # ينشئ المسؤول الأول (يطلب كلمة المرور) ويحمّل الباب الثاني وبنوده 2/1–2/29
make backup-key  # احفظ المفتاح الظاهر خارج الخادم
```

ثم افتح `https://<اسم-الخادم>`. يُلزَم المسؤول بتغيير كلمة المرور عند أول دخول، ثم ينشئ من «الإعدادات»:
1. **السنة المالية** ويختار أساس الرقابة ويفتحها.
2. **المستخدمين** بأدوارهم.
3. **الاعتماد الأصلي**، أو **استيراد سجل Excel** من «الإعدادات ← استيراد Excel».

| الأمر | الغرض |
|---|---|
| `make backup-key` | عرض مفتاح تشفير النسخ. عند النقل لخادم جديد يوضع في `.env` باسم `GBCFMS_BACKUP_KEY` قبل الاستعادة |
| `make backup` | نسخة احتياطية فورية. النسخ اليومي يعمل تلقائيًا من خدمة `scheduler` في الوقت المضبوط في الإعدادات |
| `make upgrade` | نسخة احتياطية ← بناء ← ترحيل ← إعادة تشغيل. التراجع يكون بالاستعادة من شاشة النسخ الاحتياطي |
| `make logs` / `make down` | السجلات، والإيقاف (البيانات تبقى في الـ volumes ومجلد النسخ) |

**ملاحظات:**
- nginx هو المنفذ الوحيد المنشور (443، ويحوّل 80 إليه)، ويضيف ترويسات الأمان وحد معدل لتسجيل الدخول.
- مجلد النسخ `BACKUP_DIR` يجب أن يكون قابلًا للكتابة للمستخدم 10001 داخل الحاوية: `sudo chown 10001 backups`.
- الأسرار (كلمة مرور قاعدة البيانات، سر JWT، مفتاح تشفير النسخ) تُولَّد مرة واحدة في volume باسم `secrets` ولا تُكتب في أي ملف في مجلد المشروع.
- لتفعيل المساعد الذكي: `GBCFMS_AI_ENABLED=true` و`ANTHROPIC_API_KEY` في `.env`، و`AI_HTTPS_PROXY` إذا كان الخروج إلى الإنترنت عبر وكيل.

## التطوير المحلي

```bash
# الخادم (Python 3.11+، PostgreSQL 16 مع مستخدم gbcfms/gbcfms صلاحيته إنشاء قواعد)
cd backend
python -m venv .venv
.venv/bin/python -c "import tomllib,subprocess;p=tomllib.load(open('pyproject.toml','rb'))['project'];subprocess.check_call(['.venv/bin/pip','install',*p['dependencies'],*p['optional-dependencies']['dev']])"
cp .env.example .env
.venv/bin/alembic upgrade head
.venv/bin/python -m app.cli bootstrap && .venv/bin/python -m app.cli seed-reference
.venv/bin/uvicorn app.main:app --reload            # توثيق API على /api/docs

# الواجهة (Node 22)
cd frontend && npm ci && npm run dev               # http://localhost:5173 ويمرر /api إلى 8000
```

## الاختبارات

- **الخادم:** 185 اختبارًا (يُتخطى منها اختبار الملف الحقيقي ما لم يُحدَّد مساره) على PostgreSQL حقيقي، بقاعدة جديدة لكل اختبار. تشمل الاختبارات المالية الإلزامية: سيناريو البند 41، والتزامن (30 طلبًا متزامنًا على رصيد يكفي 10 فقط)، واختبارات الخصائص (Hypothesis) لثوابت الدفتر، والإقفال السنوي، ومسار الاستيراد، وسلسلة التدقيق، والنسخ والاستعادة.

- **الملف الحقيقي:** `GBCFMS_REAL_EXCEL=/path/file.xlsx pytest tests/imports/test_real_file.py`. هذا الملف لا يُرفع إلى المستودع لاحتوائه على أسماء أشخاص.

CI في `.github/workflows/ci.yml`: الخادم (Ruff، وترحيل للأمام والخلف، والاختبارات)، والواجهة، وبناء صور النشر.
